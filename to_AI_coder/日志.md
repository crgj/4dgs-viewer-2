## 一、已修复的 Bug（9 处，已通过 `tsc --noEmit` 类型检查）

### 【高】1. 着色器编译崩溃 — 颜色轨迹/后处理 uniform 被错误嵌套进 `USE_ROTATION`
- 文件: `src/shaders/gsplat-shader.ts` (原 211-261 行附近)
- 问题: `#ifdef USE_ROTATION ... #endif` 块把 `USE_COLOR_TRAJECTORY` 的 uniform 声明、以及后处理 uniform `uBrightness/uContrast/uExposure` 都包进去了。但：
  - 后处理 uniform 在 main 中 **无条件使用**（约 634 行 `color.rgb = (color.rgb-0.5)*uContrast+0.5` 等）。
  - 颜色轨迹 uniform 在 `#ifdef USE_COLOR_TRAJECTORY` 块（约 531 行）使用，而该宏与 `USE_ROTATION` 在 `main.ts:3984-3992` 是**相互独立**定义的。
- 触发: 当模型有颜色轨迹纹理但**无旋转轨迹纹理**（`USE_COLOR_TRAJECTORY` 定义而 `USE_ROTATION` 未定义）时，uniform 未声明却被引用 → **GLSL 编译失败 → 整屏渲染崩溃**。目前未爆是因为实际 4D 模型大多同时带 rotation。
- 修复: 把颜色轨迹 uniform 声明块与三个后处理 uniform 移出 `USE_ROTATION`（后处理改为无条件声明）。`slerp`/`quatToMat3` 仍保留在 `USE_ROTATION` 内。预处理指令配对已验证平衡。

### 【高】2. 序列模式着色器编译崩溃 — strip 残留 `selectionTexture` 引用
- 文件: `src/shaders/gsplat-sequence-shader.ts`
- 问题: `stripSelectionUniforms` 用正则删掉了 `selectionTexture` 声明和选择高亮/删除检查块，但 2026-03-31 新增的「提前丢弃已删除点」块（`gsplat-shader.ts` 约 324-332 行，`textureSize/texelFetch(selectionTexture,...)`）**没被同步移除**。声明被删、引用残留 → 序列模式 (PLY4/SOG4 序列) 顶点着色器 **GLSL 编译失败**。该序列 shader 在 `main.ts:1745` 实际使用。
- 修复: 给 `stripSelectionUniforms` 追加一条 `.replace`，移除该提前丢弃块。已用 node 实测：strip 后 `selectionTexture/isSelectionMode/deletedVal/selData` 残留计数全部为 0。

### 【高】3. show.ts 播放时 lifetime 透明度动画冻结（非-4D 路径）
- 文件: `src/show.ts` `onUpdate()`（约 1176 行后）
- 问题: 播放分支里，只有 4D 路径（经 `applyVisible4DFrame`）会更新材质 `uTime`。**非-4D 路径**（有 lifetime 纹理但无 trajectory 的模型）播放时只推进 `currentTime` 和滑块，**从不更新 `uTime`**——只有暂停分支才设。shader 的 `USE_LIFETIME_TEXTURE` 透明度动画依赖 `uTime`，于是进度条在走、画面动画却卡在第 0 帧。
- 修复: 在播放分支为非-4D 情形补充 `material.setParameter('uTime', displayFrame)`（与 `main.ts` 播放分支行为一致）。

### 【中】4. show.ts 换模型后 `lastUpdatedFrame` 未重置
- 文件: `src/show.ts` `loadFile()`（约 850 行）
- 问题: `updateDynamicPositions` 用 `if (frameIdx === this.lastUpdatedFrame && this.isPlaying) return` 去重，但 `lastUpdatedFrame` 在加载新模型时未重置。若新模型首个请求帧恰好等于上个模型残留的帧号，会被误判「未变化」而跳过位置写入。
- 修复: 在 `loadFile` 状态重置区加入 `this.lastUpdatedFrame = -1`（main.ts 已有同类重置）。

### 【中-高】5. main.ts onUpdate 高频空指针崩溃 — 缺可选链
- 文件: `src/main.ts` 约 1284、1308 行
- 问题: `(this.splatEntity.gsplat as any).instance.material` 缺可选链。`instance` 在异步加载/换段瞬间可能为 `undefined`，`.material` 直接抛 `TypeError`。该代码在 `onUpdate`（每帧）执行。其它访问点（show.ts、main.ts:3304）都写成 `instance?.material`。
- 修复: 两处均改为 `instance?.material`。

### 【中-高】6. selection-tool 全时段选择 — 非激活段被错误高亮
- 文件: `src/ui/selection-tool.ts` 约 2005 行
- 问题: `currentLocalFrame` 对非激活段被赋值为 `0`（应为 `null`），而下方判断 `currentLocalFrame !== null && t === currentLocalFrame` 恒真。导致多 PLY4 全时段手工选择时，非激活段在第 0 帧被错误写入「当前帧显示通道(R)」，切到该段会看到不应有的高亮。`!== null` 守卫的存在本身证明作者原意就是非激活段应为 null。
- 修复: 非激活段改为 `null`，类型声明改为 `number | null`。

### 【中】7. smart-selection 圆柱选择 — start 边界检查被 end 条件吞掉
- 文件: `src/ui/smart-selection-tool.ts` `getSourceCurrentFrame()` 约 504 行
- 问题: `if (Number.isFinite(end) && (rawTime < start || rawTime >= end)) return null` —— 当段缺少 `globalEndFrame`（`end=NaN`）时，`rawTime < start` 的下界检查被一并跳过，使当前时间落在段起始之前时仍把第 0 帧当作当前帧。
- 修复: 拆成两条独立判断，`start` 检查独立于 `end`。

### 【低】8. viewer-file-loader 重复调用
- 文件: `src/viewer/viewer-file-loader.ts` 约 420、426 行
- 问题: `this.updateStats(asset)` 和 `v.resetCamera()` 各被连续调用两次（复制粘贴遗留）。幂等无害，但属 bug 类重复。
- 修复: 各删一行。

### 【中】9. SOG4 导出可能写入多余字节
- 文件: `src/viewer/viewer-export-manager.ts` 约 603 行
- 问题: `new Blob([buffer.buffer as ArrayBuffer], ...)` 用 `.buffer` 会包含底层 ArrayBuffer 全部字节；若 `SOG4Encoder.encode` 返回的是子视图（byteOffset≠0 或 byteLength<底层），会写入多余字节导致 `.sog4` 损坏。其它导出（PLY4/TrueSplats）都直接用 `new Blob([buffer])`。
- 修复: 改为传 Uint8Array 视图本身（尊重 byteOffset/byteLength）。因 562 行 `let buffer: Uint8Array` 显式标注致类型变宽，加 `as Uint8Array<ArrayBuffer>` 断言满足 `BlobPart`。

## 二、已发现但**未修复**的问题（需人工/原作者确认，擅自改动有回归风险）

> 以下几处要么依赖运行期数据模型、要么会改变既有行为，我没有把握在不破坏现有功能的前提下修改，**留给后续 AI/人工决策**。

### A.【需确认·可能高危】ply-exporter 静态属性索引混用 `i` vs `oidx`
- 文件: `src/utils/ply-exporter.ts` 约 131/148/200/213 行
- 现象: 轨迹/旋转/DC 纹理路径用 `oidx = round(origIndices[i])` 取值（原始顺序），而 opacity、静态 xyz、静态 rot、DC 静态值用循环下标 `i` 取值。
- 风险: 若静态属性数组与纹理数组的存储顺序不同（一个当前顺序、一个原始顺序），在「删除/重排过的 4DGS 数据 + 纹理插值路径」下会发生属性错配（xyz 与 opacity 来自不同 splat）。
- 为何没改: 是否为 bug 完全取决于这些数组的存储约定。`ply-sequence-exporter.ts` 似乎统一用 `oidx`，但我无法确认 `ply-exporter` 的静态数组到底是哪种顺序。**请原作者确认 `getS(...)`/`opacRaw`/`sh0` 返回的数组是「当前重排后顺序」还是「原始顺序」**，再决定是否统一为 `oidx`。

### B.【需确认】opacity 语义靠值域 `[0,1]` 猜测
- 文件: `src/utils/ply4-encoder.ts` `normalizeOpacityToLogit` 约 6-23 行
- 现象: 当上游未提供 `opacitySemantic` 时，用「值落在 [0,1] 就当概率做 logit 变换」的启发式。对已是 logit 且恰好落在 [0,1] 的值会被错误二次 logit 化。
- 风险: 不同 loader 路径是否都正确标注了 `opacitySemantic` 需逐一核对。改成「强制要求上游标注」是更稳的方向，但需同时审查所有 loader 的返回值，改动面大。
- 为何没改: 牵涉多个 loader 的语义契约，单点修改可能让本来正确的 TrueSplats 路径出错。

### C.【需确认·成对】autoGroundAlignment 评分函数副作用 + 自赋值死代码
- 文件: `src/algorithms/autoGroundAlignment/scoring.ts:64-66`（`scoreSupportPlane` 修改入参 `input.plane`）与 `index.ts:126`（`plane = plane;` 自赋值）
- 现象: `scoreSupportPlane` 通过副作用把定向后的法线写回入参，`index.ts:126` 的 `plane = plane` 是死代码（原意疑为 `plane = orientPlaneTowardPoint(...)`）。当前「靠副作用恰好正确」。
- 风险: 这是一对耦合问题——若只把评分函数改纯而不在 index.ts 显式定向，会导致地面法线方向错误、**场景上下颠倒**。必须成对修改并验证地面对齐结果。
- 为何没改: 当前功能正常，修复需重新验证地面对齐输出，回归风险高。

### D.【低】viewer-preset-manager 文字编辑/overlay 事件监听器泄漏
- 文件: `src/viewer/viewer-preset-manager.ts` 约 334-336、420-435 行
- 现象: `openTextEdit` / `syncTextOverlays` 每次都向 `window` 注册 `mousemove/mouseup`，元素删除后监听器仍存活。反复开关文字编辑会累积。
- 为何没改: 需要保存监听器引用并在关闭/删除时解绑，或改用单一委托监听器，改动涉及拖拽逻辑重构，建议单独处理。

### E.【非 bug·已排除】SelectionTool/SmartSelectionTool 的 window 监听器「泄漏」
- 审查中一度怀疑这两个工具每次加载都重注册全局监听器。经核实它们只在 `main.ts:275-276` **实例化一次**（应用生命周期单例），不会累积。**非 bug**，记录以免重复排查。
