# Bug 排查与修复日志

## 2026-06-12 选择后跨帧删除异常（仅分析，未改源码）

- 现象: PLY4/4D 点在 89 帧选中后，切到 71 帧因生命周期不可见，画面上没有黄色选中点；此时按 Delete 仍会删除点，且用户观察到像是删除了不相关点。
- 初步结论 1: `SelectionTool.deleteSelected()` 会同时检查 `selectionData` 当前显示通道 R 和 `allTimeSelectionData` 全时段通道 R。普通 brush/rect 选择也会把命中点写进 `allTimeSelectionData`，只在当前帧可见时才写进 `selectionData`。因此“当前帧没有黄色高亮”并不等于“没有待删除选择”；Delete 仍会按 all-time 缓冲删除 89 帧选过的点。
- 初步结论 2: 这是交互语义和 UI 表达不一致：当前帧只显示可见选中点，但删除动作按跨生命周期选区执行，缺少“隐藏选中点仍存在”的提示/计数/确认。
- 风险点: 如果用户看到的是“删了 71 帧可见的不相关点”，还需要继续验证 CPU 选择索引、`original_index` 轨迹索引、shader `splatId`/`selectionTexture` 索引是否完全同序；现有代码依赖 `i` 作为 selection 索引，同时用 `original_index[i]` 读取轨迹，若 loader/资源排序语义不一致，会出现选 A 删 B。
- 建议修改计划:
  1. 在 frame/time 改变后，按当前帧可见性从 `allTimeSelectionData` 重算 `selectionData` 的 R 通道，保证黄色显示能反映“当前帧中仍被选且可见”的点。
  2. 调整 Delete 语义：普通当前帧选择默认只删除当前可见高亮点；all-time 工具或明确 all-time scope 才删除隐藏生命周期里的选中点。
  3. Delete 前统计 `visibleSelected` 与 `hiddenSelected`。若存在 hidden 且无 visible，阻止或提示，避免“看不到选中还删除”。
  4. 加调试校验日志/测试：选择时记录命中点索引、当前帧可见性、`original_index`、删除时记录将删除的索引集合，验证 selectionTexture splatId 与 CPU 选择索引一致。

## 2026-06-12（二）根因确认 — 跨帧删除不相关点（仅分析，未改源码）

针对上一节用户复诉的两个问题，逐行核对 `performBrush`/`performRect`/`deleteSelected` 后，确认根因为**单一原因的两面**，并**排除**了上一节"风险点"中怀疑的 `original_index` 索引错位。

- 复现链路：处理单段 PLY4 → 89 帧普通 brush 选中一批点（有黄色高亮）→ 切到 71 帧，89帧的点超出生命周期不可见（无黄色）→ 按 Delete → 场景里一批"看不见也没选过"的点被删。

- 根因（关键代码）：
  - `selection-tool.ts:1604-1648` 普通 brush（`brush`，非 `brush-alltime`）的"center mode"：命中判定**只看 2D 屏幕圆**（`dx*dx+dy*dy<rSq`，且 `screen.z>0`），命中后 **`this.allTimeSelectionData[idx]=255` 是无条件写入**（1629 行，注释 "Always update all-time selection (regardless of time visibility)"）；只有 `isVisibleAtCurrentTime(i)` 才额外写 `selectionData[idx]=255`（黄色高亮）。`performRect` 1684-1720 同构。
  - `selection-tool.ts:148-150` `deleteSelected()` 判定为 `selectedNow(R) || selectedAllTime(allTime的R)`（5-16 为修多段 PLY4 切段后选区只剩 all-time 而加）。
  - 两段善意改动叠加 → 删除以 all-time 缓冲为准，而 all-time 缓冲被普通 brush 过度污染。

- 问题1（没显示选中的点被删）：删除判定用的是 `allTimeSelectionData` 而非屏幕 R 通道。89 帧刷选已把 all-time 写满，71 帧这些点 R=0（无黄色）但 all-time 仍=255 → 照删。"看不到选中" ≠ "无待删选区"。

- 问题2（删了不相关点）：普通 brush 是**纯 2D 屏幕投影，无深度测试、无时间过滤**。89 帧时任何点只要 3D 位置投影进刷子圆，就被写 `allTime=255`，**包含被遮挡点、以及属于其它时间段（如 71 帧才出生）的点**。这些点与肉眼所见的 89 帧选中物体无关，却一起进了 all-time 缓冲；71 帧 Delete 时这批"不相关点"（恰是 71 帧可见者）被删。

- **排除项**：选择与删除全程用同一个 `i` 作索引（`selectionData[i*4]` 与 brush 命中循环同序），**不是** `original_index` 轨迹索引错位、也**不是** selectionTexture splatId 不同序导致的"选 A 删 B"。上一节"风险点"可降级。

- 修复方向（待确认后实施，按把握度排序）：
  1. **首选 / 最小改动**：普通（非 all-time）工具命中时不要无条件写 all-time —— 仅对 `isVisibleAtCurrentTime(i)` 的点写 `allTimeSelectionData`（与 `selectionData` 保持一致）。这样普通刷选只捕获"当前帧可见点的跨帧轨迹"，不再吞掉其它时间段的无关点。`performBrush`/`performRect`/`performPoly` 三处对称修改。
  2. 帧切换后从 all-time 按可见性重算 R 通道（让黄色高亮反映"当前帧仍被选且可见"）。
  3. Delete 前统计 `visibleSelected` / `hiddenSelected`，若只有 hidden、无 visible，弹确认或提示，避免"看不到选中还删除"。
  4. （可选）all-time 刷选若想保留"跨遮挡"语义，应单独由 `brush-alltime` 工具承担，并在 UI 明示其会选中看不见的点。

## 2026-06-13 修复 — 普通选择不再污染 all-time 删除候选

> 作者: Codex / GPT-5
> 分支: song4+ply4
> 范围: `src/ui/selection-tool.ts`

- 修改 `deleteSelected()`：普通 Delete 只删除当前 `selectionData` R 通道中可见高亮的点；只有当前工具是 all-time 工具，或 `selectionScope === 'alltime'` 时，才会把隐藏在 `allTimeSelectionData` 里的选区一起删除。若普通 Delete 只发现 hidden all-time 选区，会输出 console warning 并跳过，避免“当前看不到黄色点却删除”的误操作。
- 修改普通 brush / rect / ellipse brush / ellipse rect：命中后不再无条件写 `allTimeSelectionData`，而是先通过 `isVisibleAtCurrentTime(i)`，只有当前帧可见的命中点才同步 all-time 缓冲。这样普通 2D 选择不会把遮挡点、其它生命周期点或当前帧不可见点塞进后续删除候选。
- 修改普通 poly：与 brush/rect 对齐，只维护当前帧可见选择，并把当前可见命中镜像到 all-time 缓冲，避免 poly 成为漏修路径。
- 保留 all-time 工具原语义：`brush-alltime` / `rect-alltime` / `poly-alltime` 仍通过全时段扫描写入 `allTimeSelectionData`，供用户明确执行跨生命周期选择和删除。
- 代码注释均按约定使用 `#WDD-gpt 2026-06-13 - [修改原因]`。

验证建议：
1. 普通 brush 在 89 帧选中可见点，切到 71 帧无黄色高亮时按 Delete，应不删除隐藏 all-time 点，并在控制台提示 skipped hidden all-time selected points。
2. 普通 brush 在 89 帧选中可见点，不切帧直接 Delete，应删除当前黄色高亮点。
3. 使用 all-time brush/rect/poly 选区后 Delete，应仍可删除 all-time 选中的隐藏生命周期点。
4. 普通 rect / ellipse / poly 重复执行同样用例，确认没有同类遗漏。

## 2026-06-13（二）新增 ALL PTS 调试渲染模式

> 作者: Codex / GPT-5
> 分支: song4+ply4
> 范围: `index.html`, `src/main.ts`, `src/shaders/gsplat-shader.ts`, `src/shaders/gsplat-sequence-shader.ts`

- 在右侧 `RENDER` 面板新增 `ALL PTS` 按钮，对应 `uRenderMode = 3`。
- `ALL PTS` 模式用固定 3px 实心小圆点显示每个 splat 中心，绕过以下普通渲染剔除：
  - lifetime 当前帧不在生命周期内导致的 `alphaMult` 近 0；
  - opacity/base alpha 近 0；
  - selectionTexture 删除通道导致的隐藏；
  - covariance/scale 过小导致的小 splat 剔除。
- `ALL PTS` 颜色诊断：
  - 红色：删除通道已标记；
  - 品红：基础透明度/opacity 过低；
  - 青色：当前帧生命周期外；
  - 原色提亮：按普通条件本应可见。
- 同步更新 `gsplat-sequence-shader.ts` 的 strip 逻辑，避免 sequence shader 因新增 ALL PTS 代码残留 `selectionTexture/selData/deletedVal` 引用而编译失败。序列模式保留固定点显示，但不做删除/生命周期颜色诊断。

排查结论：
- 除生命周期外，当前 shader 里还会让点不可见的主要原因包括：opacity/base alpha 太低、被删除通道标记、covariance/scale 太小、fragment 透明度低于 1/255、点在相机背后或视锥外。
- `ALL PTS` 已绕过前四类数据原因；相机背后/视野外属于观察视角问题，需要转动或缩放相机确认。

## 一、已修复的 Bug（9 处，已通过 `tsc --noEmit` 类型检查）

### 【高】1. 着色器编译崩溃 — 颜色轨迹/后处理 uniform 被错误嵌套进 `USE_ROTATION`
- 文件: `src/shaders/gsplat-shader.ts` (原 211-261 行附近)
- 问题: `#ifdef USE_ROTATION ... #endif` 块把 `USE_COLOR_TRAJECTORY` 的 uniform 声明、以及后处理 uniform `uBrightness/uContrast/uExposure` 都包进去了。但：
  - 后处理 uniform 在 main 中 **无条件使用**（约 634 行 `color.rgb = (color.rgb-0.5)*uContrast+0.5` 等）。
  - 颜色轨迹 uniform 在 `#ifdef USE_COLOR_TRAJECTORY` 块（约 531 行）使用，而该宏与 `USE_ROTATION` 在 `main.ts:3984-3992` 是**相互独立**定义的。
- 触发: 当模型有颜色轨迹纹理但**无旋转轨迹纹理**（`USE_COLOR_TRAJECTORY` 定义而 `USE_ROTATION` 未定义）时，uniform 未声明却被引用 → **GLSL 编译失败 → 整屏渲染崩溃**。目前未爆是因为实际 4D 模型大多同时带 rotation。
- 修复: 把颜色轨迹 uniform 声明块与三个后处理 uniform 移出 `USE_ROTATION`（后处理改为无条件声明）。`slerp`/`quatToMat3` 仍保留在 `USE_ROTATION` 内。预处理指令配对已验证平衡。

### 【高】2. 序列模式着色器编译崩溃 — strip 残留 `selectionTexture` 引用
- 文件: `src/shaders/gsplat-sequence-shader.ts`
- 问题: `stripSelectionUniforms` 用正则删掉了 `selectionTexture` 声明和选择高亮/删除检查块，但 2026-03-31 新增的「提前丢弃已删除点」块（`gsplat-shader.ts` 约 324-332 行，`textureSize/texelFetch(selectionTexture,...)`）**没被同步移除**。声明被删、引用残留 → 序列模式 (PLY4/SOG4 序列) 顶点着色器 **GLSL 编译失败**。该序列 shader 在 `main.ts:1745` 实际使用。
- 修复: 给 `stripSelectionUniforms` 追加一条 `.replace`，移除该提前丢弃块。已用 node 实测：strip 后 `selectionTexture/isSelectionMode/deletedVal/selData` 残留计数全部为 0。

### 【高】3. show.ts 播放时 lifetime 透明度动画冻结（非-4D 路径）
- 文件: `src/show.ts` `onUpdate()`（约 1176 行后）
- 问题: 播放分支里，只有 4D 路径（经 `applyVisible4DFrame`）会更新材质 `uTime`。**非-4D 路径**（有 lifetime 纹理但无 trajectory 的模型）播放时只推进 `currentTime` 和滑块，**从不更新 `uTime`**——只有暂停分支才设。shader 的 `USE_LIFETIME_TEXTURE` 透明度动画依赖 `uTime`，于是进度条在走、画面动画却卡在第 0 帧。
- 修复: 在播放分支为非-4D 情形补充 `material.setParameter('uTime', displayFrame)`（与 `main.ts` 播放分支行为一致）。

### 【中】4. show.ts 换模型后 `lastUpdatedFrame` 未重置
- 文件: `src/show.ts` `loadFile()`（约 850 行）
- 问题: `updateDynamicPositions` 用 `if (frameIdx === this.lastUpdatedFrame && this.isPlaying) return` 去重，但 `lastUpdatedFrame` 在加载新模型时未重置。若新模型首个请求帧恰好等于上个模型残留的帧号，会被误判「未变化」而跳过位置写入。
- 修复: 在 `loadFile` 状态重置区加入 `this.lastUpdatedFrame = -1`（main.ts 已有同类重置）。

### 【中-高】5. main.ts onUpdate 高频空指针崩溃 — 缺可选链

- 问题: `(this.splatEntity.gsplat as any).instance.material` 缺可选链。`instance` 在异步加载/换段瞬间可能为 `undefined`，`.material` 直接抛 `TypeError`。该代码在 `onUpdate`（每帧）执行。其它访问点（show.ts、main.ts:3304）都写成 `instance?.material`。

### 【中-高】6. selection-tool 全时段选择 — 非激活段被错误高亮

- 问题: `currentLocalFrame` 对非激活段被赋值为 `0`（应为 `null`），而下方判断 `currentLocalFrame !== null && t === currentLocalFrame` 恒真。导致多 PLY4 全时段手工选择时，非激活段在第 0 帧被错误写入「当前帧显示通道(R)」，切到该段会看到不应有的高亮。`!== null` 守卫的存在本身证明作者原意就是非激活段应为 null。
- 修复: 非激活段改为 `null`，类型声明改为 `number | null`。

### 【中】7. smart-selection 圆柱选择 — start 边界检查被 end 条件吞掉

- 修复: 拆成两条独立判断，`start` 检查独立于 `end`。

- 问题: `this.updateStats(asset)` 和 `v.resetCamera()` 各被连续调用两次（复制粘贴遗留）。幂等无害，但属 bug 类重复。
- 修复: 各删一行。

### 【中】9. SOG4 导出可能写入多余字节
- 文件: `src/viewer/viewer-export-manager.ts` 约 603 行
- 问题: `new Blob([buffer.buffer as ArrayBuffer], ...)` 用 `.buffer` 会包含底层 ArrayBuffer 全部字节；若 `SOG4Encoder.encode` 返回的是子视图（byteOffset≠0 或 byteLength<底层），会写入多余字节导致 `.sog4` 损坏。其它导出（PLY4/TrueSplats）都直接用 `new Blob([buffer])`。

## 二、已发现但**未修复**的问题（需人工/原作者确认，擅自改动有回归风险）

> 以下几处要么依赖运行期数据模型、要么会改变既有行为，我没有把握在不破坏现有功能的前提下修改，**留给后续 AI/人工决策**。

### A.【需确认·可能高危】ply-exporter 静态属性索引混用 `i` vs `oidx`
- 文件: `src/utils/ply-exporter.ts` 约 131/148/200/213 行
- 现象: 轨迹/旋转/DC 纹理路径用 `oidx = round(origIndices[i])` 取值（原始顺序），而 opacity、静态 xyz、静态 rot、DC 静态值用循环下标 `i` 取值。
- 风险: 若静态属性数组与纹理数组的存储顺序不同（一个当前顺序、一个原始顺序），在「删除/重排过的 4DGS 数据 + 纹理插值路径」下会发生属性错配（xyz 与 opacity 来自不同 splat）。
- 为何没改: 是否为 bug 完全取决于这些数组的存储约定。`ply-sequence-exporter.ts` 似乎统一用 `oidx`，但我无法确认 `ply-exporter` 的静态数组到底是哪种顺序。**请原作者确认 `getS(...)`/`opacRaw`/`sh0` 返回的数组是「当前重排后顺序」还是「原始顺序」**，再决定是否统一为 `oidx`。

### B.【需确认】opacity 语义靠值域 `[0,1]` 猜测
- 文件: `src/utils/ply4-encoder.ts` `normalizeOpacityToLogit` 约 6-23 行
- 现象: 当上游未提供 `opacitySemantic` 时，用「值落在 [0,1] 就当概率做 logit 变换」的启发式。对已是 logit 且恰好落在 [0,1] 的值会被错误二次 logit 化。
- 风险: 不同 loader 路径是否都正确标注了 `opacitySemantic` 需逐一核对。改成「强制要求上游标注」是更稳的方向，但需同时审查所有 loader 的返回值，改动面大。
- 为何没改: 牵涉多个 loader 的语义契约，单点修改可能让本来正确的 TrueSplats 路径出错。

### C.【需确认·成对】autoGroundAlignment 评分函数副作用 + 自赋值死代码
- 文件: `src/algorithms/autoGroundAlignment/scoring.ts:64-66`（`scoreSupportPlane` 修改入参 `input.plane`）与 `index.ts:126`（`plane = plane;` 自赋值）
- 现象: `scoreSupportPlane` 通过副作用把定向后的法线写回入参，`index.ts:126` 的 `plane = plane` 是死代码（原意疑为 `plane = orientPlaneTowardPoint(...)`）。当前「靠副作用恰好正确」。
- 风险: 这是一对耦合问题——若只把评分函数改纯而不在 index.ts 显式定向，会导致地面法线方向错误、**场景上下颠倒**。必须成对修改并验证地面对齐结果。
- 为何没改: 当前功能正常，修复需重新验证地面对齐输出，回归风险高。

### D.【低】viewer-preset-manager 文字编辑/overlay 事件监听器泄漏
- 文件: `src/viewer/viewer-preset-manager.ts` 约 334-336、420-435 行
- 现象: `openTextEdit` / `syncTextOverlays` 每次都向 `window` 注册 `mousemove/mouseup`，元素删除后监听器仍存活。反复开关文字编辑会累积。
- 为何没改: 需要保存监听器引用并在关闭/删除时解绑，或改用单一委托监听器，改动涉及拖拽逻辑重构，建议单独处理。

### E.【非 bug·已排除】SelectionTool/SmartSelectionTool 的 window 监听器「泄漏」
- 审查中一度怀疑这两个工具每次加载都重注册全局监听器。经核实它们只在 `main.ts:275-276` **实例化一次**（应用生命周期单例），不会累积。**非 bug**，记录以免重复排查。
